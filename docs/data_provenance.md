# Data provenance

## Source

**Every record in this repository is synthetic.** It is produced by `src/swasthtwin/data_generator.py`
from a fixed seed (`seed: 2026` in `config/model_config.yaml`). No real patient data, no external dataset,
and no download is used. Because the data is generated by this project's own MIT-licensed code, no
third-party dataset licence applies to it.

Re-create it exactly with `make data`. Changing the seed or cohort size in the config produces a different
but equally reproducible cohort.

## How the glucose signal is simulated

A simple additive model, run per patient on a 5-minute grid:

```
glucose(t) = basal                     # from the patient's EHR fasting glucose
           + daily offset + AR(1) drift
           + dawn-phenomenon bump      # patient-specific size, centred ~06:30
           + Σ meal carbs × carb sensitivity × meal-response curve (peak 35–80 min)
           − Σ steps × exercise sensitivity × exercise-response curve
           + stress episodes           # also raise heart rate and lower HRV
           + short-sleep penalty       # next day: higher basal, higher carb sensitivity
```

* **EHR → physiology link (assumption):** carb sensitivity = (0.45 + 0.45 × (HbA1c − 5.5) + 0.02 × (BMI − 25))
  × medication factor (0.80–1.0) × patient noise. Medication factors are illustrative, **not** drug-effect claims.
* **Behaviour:** 3 meals a day (+ optional snack) around patient wake time, 13:30 and 20:30; weekend meals
  ~15 % larger; post-meal walks with patient-specific probability; background steps while awake.
* **Measurement:** CGM noise, sensor gaps, watch-off hours and incomplete, noisy meal logs.

All coefficients were chosen by hand to give plausible-looking ranges (T2D mean CGM ≈ 181 mg/dL,
prediabetes ≈ 115 mg/dL in the default cohort). **They are not fitted to, or validated against, any real data.**

## Known artefacts of the simulator (important for interpreting results)

1. **Regular meal times.** Meals cluster around fixed clock times, so time of day is strongly predictive.
   The trained model uses this (it is among the top permutation-importance features). Real patients are
   less regular; this inflates performance.
2. **Patient level dominates.** High-HbA1c patients are above 180 mg/dL much of the day, so "who" explains a
   lot of the label. We report a harder subset (glucose not yet ≥ 180) for this reason.
3. **No hypoglycemia dynamics, no insulin dosing model, no illness, no menstrual cycle, no CGM lag.**
4. **Simple, additive, deterministic structure** — easier to learn than real physiology.

## External datasets

None are used. A future step (see README roadmap) is to evaluate on public, de-identified CGM datasets.
Before any such use the team must verify the original source, access conditions, licence and attribution
requirements, and record them here. The synthetic pipeline must remain as a working fallback.
